透明渲染不仅取决于纹理是否包含 Alpha 通道，还取决于渲染顺序、混合状态、深度测试和深度写入策略。如果这些状态没有协同工作，即使纹理本身的透明通道完全正确，最终画面仍可能出现异常。

## 透明渲染原理

纹理的透明通道通常由 Alpha 值表示：

- `Alpha = 1`：完全不透明；
- `Alpha = 0`：完全透明；
- `0 < Alpha < 1`：半透明。

透明像素一般通过 Alpha Blending 与当前 Framebuffer 中已有的颜色混合：

```glsl
FinalColor =
    SourceColor * SourceAlpha
    + DestinationColor * (1.0 - SourceAlpha);
```

其中，`SourceColor` 是当前正在绘制的物体颜色，`DestinationColor` 是 Framebuffer 中原有的背景颜色。因此，透明物体必须在需要透出的背景之后绘制，否则它只能与 Clear Color 或错误的背景内容混合。

![](IMG-20260809135814495.png "Alpha Blending 中的 Source 与 Destination。当前片元颜色作为 Source，Framebuffer 中已有的颜色作为 Destination")

- 绿色方块是当前片元输出，即 Source；
- 红色方块是颜色缓冲中已有内容，即 Destination；
- Source 的 Alpha 为 `0.6`。

![](IMG-20260809135845541.png "混合结果")

### 2D透明处理

2D Sprite 通常是带有 RGBA 纹理的矩形。透明效果直接来自纹理 Alpha 与实体 Tint Alpha 的乘积：

```glsl
vec4 sampledColor = texture(u_Texture, v_TexCoord);
vec4 finalColor = sampledColor * v_Color;
```

2D 透明渲染主要依赖：

1. 开启 Alpha Blending；
2. 在背景和天空盒之后绘制；
3. 正确处理深度测试与深度写入；
4. 必要时丢弃完全透明的像素。

![](IMG-20260809135955973.png "错误透明顺序")

如果 Sprite 在天空盒之前绘制，透明像素会先与 Clear Color 混合；如果这些像素同时写入深度，之后绘制的天空盒还可能无法覆盖它们。

因此，本项目将 2D Sprite Pass 放在天空盒之后：

```
Opaque 3D → Terrain → Skybox → 2D Sprite
```

### 3D透明处理

3D 透明比 2D 更复杂，因为不同模型以及同一模型的不同表面之间存在前后深度关系。

对于普通不透明物体，深度缓冲可以直接决定可见表面，绘制顺序通常不会明显影响结果。但 Alpha Blending 会读取 Framebuffer 中已有的颜色，因此透明物体通常需要从远到近绘制。

本项目将 3D 材质分为三种模式：

- `Opaque`：完全不透明，关闭混合并写入深度；
- `Mask`：根据 AlphaCutoff 丢弃像素，其余像素按不透明方式处理；
- `Blend`：保留半透明渐变，开启混合和深度测试，但关闭深度写入。

Blend 模式采用：

```
SourceAlpha
OneMinusSourceAlpha
```

对应的混合公式为：

```
结果颜色 =
    当前透明物体颜色 × 当前 Alpha
    + 后方已有颜色 × (1 - 当前 Alpha)
```

透明 3D 实体按照到相机的距离由远到近排序：

```
远处透明物体 → 近处透明物体
```

最终渲染顺序为：

```
Opaque/Mask 3D
    → Terrain
    → Skybox
    → 2D Sprite
    → Transparent 3D
```

这种处理能够满足大多数普通透明模型，但仍不能完全解决单个复杂模型内部的三角形自相交问题。更复杂的透明效果通常需要逐三角形排序、加权混合透明或其他 Order-Independent Transparency 技术。

## 2D渲染

在场景中测试带透明通道的 2D 纹理时，发现透明区域没有显示后方的天空盒，而是显示成了 Framebuffer 的 Clear Color。

![](IMG-20260809123510569.png "位于3Dmesh上，看不出")

![](IMG-20260809123558629.png "由于渲染顺序出错导致")

最初看起来像是纹理 Alpha 通道没有被正确读取，或者透明混合状态没有开启。但检查纹理数据后确认图片确实包含有效的透明通道，因此进一步使用 RenderDoc 对当前帧进行抓取。

### RenderDoc分析

通过RenderDoc抓帧验证得确实是渲染顺序的问题，从 RenderDoc 的 Event Browser 中可以看到，Renderer2D 的 Draw Call 发生在 Skybox Draw Call 之前。

![](IMG-20260809123704655.png "2D渲染时，skybox尚未开始渲染，故错误留下了通道")

![](IMG-20260809123725788.png)

这就是问题的根本原因。

2D 图片的透明像素虽然经过了 Alpha 混合，但它们是在天空盒绘制之前与 Clear Color 混合的。更重要的是，颜色混合不会自动阻止深度写入：透明像素仍可能写入深度缓冲，导致后续天空盒无法通过深度测试。

因此最终看到的不是后方天空盒，而是透明像素先前混合得到的 Clear Color。

### 调整渲染顺序

正确的处理方式是将完整的 Sprite Pass 延迟到天空盒绘制完成之后：

编辑器中的主要调用顺序调整为：

```cpp
SkyboxRenderer::Draw(
    cubemap->GetTexture(),
    m_SkyboxShader,
    skyboxView,
    skyboxProjection,
    skyLight.Intensity
);

m_ActiveScene->FlushSpritePass();
Renderer3D::EndScene();
```

这里不能只延迟 `Renderer2D::EndScene()`。

Renderer2D 使用批处理渲染。当索引数量或纹理槽达到上限时，`DrawSprite()` 可能在提交过程中自动触发 `Flush()`。如果只延迟 `EndScene()`，部分 2D Draw Call 仍有可能提前发生。

因此，最终方案是在 Scene 更新阶段只记录 Sprite Pass 所需的 ViewProjection，不立即遍历和提交 Sprite：

```cpp
if (deferSpritePass)
{
    m_DeferredSpriteViewProjection = viewProjection;
    m_SpritePassPending = true;
}
else
{
    RenderSprites(viewProjection);
}
```

等天空盒完成后，再执行完整的 Sprite 遍历、批处理和提交：

```cpp
void Scene::FlushSpritePass()
{
    if (!m_SpritePassPending)
        return;

    RenderSprites(m_DeferredSpriteViewProjection);
    m_SpritePassPending = false;
}

void Scene::RenderSprites(const glm::mat4& viewProjection)
{
    Renderer2D::BeginScene(viewProjection);

    auto group = m_Registry.group<TransformComponent>(
        entt::get<SpriteRendererComponent>
    );

    for (auto entity : group)
    {
        // 获取 TransformComponent 与 SpriteRendererComponent
        // 并调用 Renderer2D::DrawSprite(...)
    }

    Renderer2D::EndScene();
}
```

这样能够保证 Renderer2D 内部的所有 Draw Call，包括由批次容量触发的自动 Flush，都发生在天空盒之后。

修复后的结果如下：

![](IMG-20260809125310543.png)

现在 2D 纹理的透明区域会与已经绘制完成的天空盒正确混合，不再显示 Clear Color。

## 3D渲染

完成 2D 顺序修复后，又对 3D 模型的透明渲染进行了验证。

![](IMG-20260809130343739.png)

### 3D纹理贴图支持

当前 3D 材质已经支持 BaseColor 纹理贴图。OBJ 模型加载时会读取顶点 UV，PBR Shader 使用 UV 对 BaseColorTexture 进行采样：

```glsl
vec4 sampledColor = vec4(1.0);

if (u_HasBaseColorTexture != 0)
{
    sampledColor = texture(
        u_BaseColorTexture,
        v_TexCoord * u_TilingFactor
    );
}

vec3 linearBaseColor =
    pow(max(u_BaseColor.rgb, vec3(0.0)), vec3(2.2));

vec3 albedo = linearBaseColor * sampledColor.rgb;
```

最终透明度由材质颜色和纹理 Alpha 共同决定：

```glsl
float effectiveAlpha = clamp(
    u_BaseColor.a * sampledColor.a,
    0.0,
    1.0
);
```

当前材质提供三种 AlphaMode。

### Opaque

Opaque 用于完全不透明的物体。

即使 BaseColor 纹理包含透明通道，最终输出 Alpha 仍固定为 1：

```glsl
float outputAlpha =
    u_AlphaMode == 0 ? 1.0 : effectiveAlpha;
```

Opaque 关闭混合、开启深度写入，并可以参与 Instancing 合批。

![](IMG-20260809140123039.png "OPAQUE 与 BLEND 的区别。OPAQUE 忽略纹理中的 Alpha；BLEND 使用连续 Alpha 与背景进行混合")

### Mask

Mask 用于树叶、铁丝网、镂空装饰等只有“显示”和“不显示”两种状态的材质。

```glsl
if (u_AlphaMode == 1 &&
    effectiveAlpha < u_AlphaCutoff)
{
    discard;
}
```

Alpha 小于 `AlphaCutoff` 的片元被直接丢弃，不写入颜色、深度或 EntityID。

Mask 不产生半透明过渡，但仍然可以写入深度，并保留不透明队列的排序和 Instancing 优势。

![](IMG-20260809140202234.png "MASK 模式下不同 AlphaCutoff 的效果。阈值越大，被丢弃的片元越多；最终结果只有完全显示和完全透明两种状态")

### Blend

Blend 用于玻璃、烟雾以及具有渐变透明边缘的材质。

为了防止完全透明的像素继续写入 EntityID，Shader 会丢弃接近零 Alpha 的片元：

```glsl
if (u_AlphaMode == 2 &&
    effectiveAlpha <= (1.0 / 255.0))
{
    discard;
}
```

Blend 材质会进入独立的透明队列，并根据实体位置到相机的距离进行由远到近排序：

```cpp
std::stable_sort(
    transparentQueue.begin(),
    transparentQueue.end(),
    [](const RenderItem& left, const RenderItem& right)
    {
        return left.CameraDistanceSquared >
               right.CameraDistanceSquared;
    }
);
```

绘制透明队列时使用标准 Alpha 混合：

```cpp
RenderCommand::SetBlendFunction(
    BlendFactor::SourceAlpha,
    BlendFactor::OneMinusSourceAlpha
);

RenderCommand::SetBlendEnabled(true);
RenderCommand::SetDepthWriteEnabled(false);
RenderCommand::SetDepthFunction(DepthFunction::Less);
```

这里的状态组合非常重要：

- 开启深度测试，使透明物体仍能被前方不透明物体遮挡；
- 关闭深度写入，避免较早绘制的透明表面阻挡后续透明物体；
- 按距离由远到近绘制，使多个透明物体的混合结果尽量正确；
- 使用 `SourceAlpha / OneMinusSourceAlpha` 完成标准透明混合。

绘制结束后，还需要恢复默认状态，防止透明状态影响下一帧：

```cpp
RenderCommand::SetBlendEnabled(false);
RenderCommand::SetDepthWriteEnabled(true);
RenderCommand::SetDepthFunction(DepthFunction::Less);
```

### 当前完整渲染顺序

经过调整后，当前场景的主要渲染顺序为：

```
Opaque/Mask Models
        ↓
Terrain
        ↓
Skybox
        ↓
2D Sprite
        ↓
Transparent Models
```

其中：

- Opaque 和 Mask 负责建立稳定的深度信息；
- 天空盒填充仍未被实体覆盖的背景；
- 2D Sprite 在天空盒之后混合，避免透明区域显示 Clear Color；
- Blend 3D 模型最后按照相机距离由远到近绘制。

### 当前限制

目前透明 3D 的排序单位是“实体”，距离取自实体 Transform 的位置，而不是模型中每个三角形的实际深度。

因此，多个独立透明实体通常可以得到正确结果，但单个复杂透明模型如果存在自相交或前后表面重叠，仍可能出现透明排序错误。

此外，目前 2D Sprite 和透明 3D 模型之间还没有统一的跨队列距离排序。当前采用固定顺序：

```
2D Sprite → Transparent 3D
```

这足以解决本次透明区域显示 Clear Color 的问题，但如果以后需要处理 2D 与透明 3D 相互穿插的复杂场景，还需要进一步设计统一的透明渲染队列。
